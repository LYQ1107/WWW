# Method differentiation

Full uses one global visual state, multi-token dynamic typed QuestionReader, own-question OptionReader, actual option-state cross-read, question gate, masked typed choice and lawful native assignment. This is a distinct executable interface, not an accept/reject wrapper around GTA. CAMEL-style/MOTIP-style/Set controls share evidence/state front-end and masks, but ordinary four-layer candidate/context decoders have no Jev QuestionReader or question gate. They are adaptations, not official full-system reproductions. Active parameter/MAC comparison is reported before training.

A named Jev implementation is not evidence of scientific advantage. Only same features, native executor, lawful options, GT labels and optimizer budget comparisons/ablations can support independent value. Original GMT is a strong full-system comparator; its different Stage2-trained frontend makes it a separate comparison. Full future lifecycle learning requires real task supervision; MEMORY defaults to native WRITE, never a random head.

Training choices are dense native events, not selected corrective132 examples, and no old GMT_OFF H32 labels enter the objective. Cross-camera pixel positions are never compared as if calibrated. The bank is global, camera-specific observations are retained, and IDs remain opaque Python references.
