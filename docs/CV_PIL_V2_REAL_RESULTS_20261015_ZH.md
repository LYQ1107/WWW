# CV-PIL V2：冻结原生历史的等容量对照

## 结论与研究状态

完成固定的 C2/C3/C4 各300步 CPU 实验。当前主状态为 **INSUFFICIENT_NATIVE_OPPORTUNITY**，本轮预测目标的诊断为 **NO_UNIQUE_PREDICTIVE_EFFECT**。C3 没有超过 C2，且开发查询的所有首选候选与 C4 完全相同。不能声称身份关联或在线跟踪改善；不启动原生部署和完整视频评测。

P0 来源契约和测试、P1 三个必要对照均已执行。P2 等待另一分支发布冻结、合法、SHA绑定的全量 TRAIN 挖掘交接；已有 `aggregate_snapshot.json` 在观察时状态为 `INCOMPLETE`，不是发布产物，本分支未消费其中的新事件、重采视频或重复挖掘。

本轮失败不取消已预注册的后续必要对照。未来发布的新范围仍须先核验来源、原生实际错误、可达正例和固定划分，再在授权预算内执行匹配对照；不能用当前开发结果事后挑选有利场景。

## 固定输入、模型与训练

继承 `adc3739a` 的交接协议，数据为 TrackVGGT 已冻结的1000个训练查询（TRAIN4/5/6/7/8）和300个开发查询（TRAIN12）。冻结 cohort SHA256：

`2ea0d5a054cd507a66c645c0288189eca3b6dfdaf7640b96b2b6d1def73cf7a1`

六个来源包的 manifest 和 events 分别绑定到 cohort SHA；checkpoint/config、候选原生 ID/列号/分数、Top8、历史归属、物理观测来源和1152维特征均经过校验。使用完整原生1152维向量，不任意截取1024维；这是含原生外观及空间/相机信息的表示，不是经过证明的纯身份表示。

所有模型均38,080个参数，rank16、同一零残差初始化、同一随机种子20261015、同一采样表、每个300次更新、AdamW(lr0.001, weight_decay0.0001)、梯度范数上限1、原生分数融合尺度2。历史年龄除以400并限幅，残差尺度0.25。最终使用step300，不按开发成绩选模型。

- **C0**：缓存的原生 GMT 轨迹级分数，含原生按参考块激活、按轨迹汇总的语义；不是上一轮逐历史帧原始 GTA logit 诊断，不能混算。
- **C1**：相同分数加严格历史的普通余弦，零训练参数。
- **C2**：普通低秩历史候选排序器，仅排序目标。
- **C3**：与C2相同网络，额外0.5权重的跨视角潜在预测目标。预测器只看严格历史特征、目的相机和时间间隔；较晚的当前查询特征只作为离线 TRAIN 的 stop-gradient 监督目标。
- **C4**：与C3相同参数，显式相机条件通道置零，保留时间条件。

1000个训练查询全部保留在记录和评价中。855个满足共同的已认证正例、已认证负例和非空严格历史监督条件，固定采样300次、涉及251个不重复训练查询；采样表和资格查询键完整留存。三个训练臂都有285步具有跨视角正例历史监督。UNKNOWN 候选只在监督损失中屏蔽，在推理和排序指标中仍是原来的合法候选；别名轨迹使用多正例目标，不把同一人的其他原生ID当成负例。

GMT、GTA、检测器、GMT+MLP、DINOv2、VGGT均未训练或调用。GMT+MLP 只冻结检查点 SHA，作为未来在线阶段的独立参考，未在不兼容的缓存接口上伪造分数。

## 开发集真实结果

300个查询中有218个已知 GT 查询，100个包含已认证正例。下表 Top-1/MRR 的分母是这100个正例可覆盖查询，排序时保留全部原生Top8，包括 UNKNOWN；不是300个查询上的身份准确率。

“认证排序纠错/反改错”要求前后均能用纯净轨迹标签判断，分别是已知错误→正确、正确→已知错误；UNKNOWN转换另外计数。它们不等于原生提交纠错。

| 方法 | Top-1 | MRR | 认证排序纠错 / 反改错，相对C0 | 首选UNKNOWN（全部300查询） |
|---|---:|---:|---:|---:|
| C0 原生GMT分数 | 66/100 | 0.813333 | — | 216/300 |
| C1 普通历史余弦 | 67/100 | 0.818333 | 1 / 0 | 216/300 |
| C2 普通排序学习 | 67/100 | 0.818333 | 1 / 0 | 216/300 |
| C3 跨视角预测目标 | 66/100 | 0.813333 | 0 / 0 | 216/300 |
| C4 去显式相机预测 | 66/100 | 0.813333 | 0 / 0 | 216/300 |

相对C2，C3认证排序纠错0、反改错1，涉及1个人物依赖组；相对C4，C3认证纠错和反改错均0，开发集首选原生ID完全一致。C3没有显示所需独立价值。

候选覆盖率：全部查询100/300=33.33%，已知查询100/218=45.87%。查询本身UNKNOWN为82/300=27.33%；首选结果UNKNOWN为216/300=72%。其中原生Top1有134个模糊轨迹标签、82个未知查询，不把这些216项说成216次错误。开发集有13个多正例别名查询，严格历史跨视角正例仅11个查询。

开发数据只有1个场景、7个人物依赖组；人物平均Top-1为 C0/C3/C4=0.562837、C1/C2=0.566321。完整逐场景、逐人物指标及查询键在结果JSON/CSV，不用候选边数当成独立成功次数。

唯一被 C1/C2 排对而 C3/C4 没排对的例子：`[scene12, image29959, row5]`，GT person3。C0/C3/C4首选原生ID6，C1/C2首选ID3。原始主关联状态已经是 `correct_link`。这表明候选Top1与原生求解结果不同；对这条排序做修正不能据此算作修复了原生身份错误。

## 原生机会与训练集诊断

开发集的已知Top1错误共18个，但原始主关联结果没有 `wrong_link` 或 `missed_known_positive`。主关联状态分布：77正确、138模糊引用、82未知查询、2在已记录候选内正确拒绝、1候选覆盖未知。没有可据以认证的 wrong/missed 原生开发机会，且该旧导出只认证primary-before-memory，并未认证 Bank/birth 的最终身份。

因此新模型的“真实原生最终提交纠错、反改错”均记为 **null / 尚未测量**，不能把排序的1或0填成在线结果。全量挖掘分支的新发布必须提供实际提交证据和可达候选。
