# Phase XIII: GMT and actual Stage1 audit

Actual weights and function hashes are recorded in STAGE1_CHECKPOINT_AUDIT.json. Stage1 model_16000.pth contains 411 model keys and a verified 4000+16000 continuation of the 20000-update schedule. REID=True routes `_forward_asso_gmt` through FCHead VFCE1024 and classification/triplet/center supervision; backbone/proposal/VFCE tensors changed. Stage1 RPCE and GTA tensors remained unchanged in the continuation, while Stage2 REID=False changed s_t_head RPCE128 and GTA transformer. ATTWeightHead has zero projection layers and no trained scoring parameters in this config; it returns query-key dot products after GTA.

DLA/BiFPN produces the actual p3 ROI features; ROIPooler7 and FCHead produce VFCE. Eval `_forward_asso` otherwise adds jitter and concatenates RPCE to1152. The new frontend instead pools the same unjittered proposal ROIs used in Stage1 identity training, outputs1024, and raises on GTA/RPCE calls. It runs the real Stage1 detector again, so detector changes relative to Original GMT are not an association-only causal effect.

Original association functions: `_forward_transformer` consumes history proposal embeddings with randomized trajectory slots; ATTWeightHead computes proposal logits; `_activate_asso` adds a zero unmatched logit per historical frame; tracker sums proposal probabilities into identity scores, applies Hungarian and history-dependent thresholds, then queries native stale bank and writes committed observations. `run_first_tracker_plus` initializes the other camera after largest-camera bootstrap. `run_global_tracker_plus`, `memory_bank`, `run_memory_tracker` manage ID counter, ordered Gallery, poss_ids/old_reids and native recovery. Full function bodies/line ranges were audited and SHA-bound.

Important provenance limitation: the actual Stage1 dataset includes all24 official TRAIN videos, including17/18/19 and20/21/22. These inherited features do not permit claims of end-to-end independent validation or heldout generalization. New Phase XIII Stage2 training labels are restricted to12/13/14/16.17/18/19 remain repeatedly used development data.20/21/22 are kept sealed; G9 cannot pass with this inherited frontend. No official TEST data is read. A future independent system would require retraining an audited frontend excluding all evaluation scenes, with a new preregistered split.

GMT_BASELINE_FREEZE keeps complete raw-online Original GMT metrics from Phase XII and the original Stage2 checkpoint SHA. It is the strong original system comparison, separate from the common-Stage1 feature experiment. Phase XII and prior results are unchanged.
