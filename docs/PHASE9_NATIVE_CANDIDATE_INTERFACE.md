# Phase IX native candidate-values interface

Default-disabled opt-in config: MODEL.JEV.CANDIDATE_ENABLED, CANDIDATE_POLICY and CANDIDATE_SCRIPTED_MODEL. Existing GMT OFF scoring, solve and commit remain the compatibility anchor. The non-multicamera sliding_inference calls a different historical run_global_tracker and is not claimed as integrated; VisionTrack's actual two-camera entry is sliding_inference_GMT -> run_first_tracker_plus / run_global_tracker_plus -> MATCH -> bank -> birth/MEMORY -> next live get_asso.

CandidateBatch supplies state64, shared prefix-only evidence12, finite legal mask, raw GMT scores, per-candidate acceptance thresholds and runtime identity references. model_inputs excludes identity integers. The production value policy accepts a scripted module with (state64,evidence12,mask)->(values[D,C],NEW[D]); no trained candidate checkpoint exists yet. GMT scores and bidirectional normalization are fixed controls. The canonical 12 fields are named in jev_candidate_features.py; this Phase IX definition replaces gap/stale indicators with actual native hit/bank eligibility fields and uses gallery mean cosine. Phase VIII labels/protocol are not altered; old feature packets cannot silently be used as the new training input.

assign_candidate_values solves one camera's entire matrix with one private NEW dummy per row. A combined-view call groups scopes and permits legitimate cross-camera reuse. Runtime references canonicalize tied choices but never enter neural features. Finite masks, duplicates, empty/all-masked/zero-detection/high-cardinality sets have explicit contracts. GMT compatibility uses existing-only rectangular Hungarian followed by native candidate-length threshold; this deliberately different objective is reported as an anchor, not an identical-objective learned comparison. All future candidate architectures share the augmented values solve and semantic NEW.

An explicit candidate NEW bypasses the current row's stale-bank recovery and then uses the unchanged native birth counter/gallery commit. GMT compatibility unmatched rows still pass to the original bank. Selected existing references go through unchanged native MEMORY and counts. This semantic distinction is common to all candidate value controllers. No solver monkey-patch is used for production integration. An optional observational commit hook exposes complete actual mutable containers for parity tests without changing assignment.

**WHAT DID WE LEARN?** Helper ID equality alone misses bank and birth effects. Eighteen adversarial solver/producer tests pass; full deployed compatibility and real mutated continuation are independently tested and must be accepted before formal learning. Refer to NATIVE_COMMIT_PARITY.json for the actual scope; pending or untested cases are not PASS.
