## 二、首先回答一个必须解决的科学问题

为什么 R2 的 JEV 在两个辅助任务上明显强于 Pair Threshold，但最终关联方案排名没有优势？

已知 TRAIN16 Pilot：

Cross 正例：
JEV 945/1001；
Pair Threshold 702/1001。

Stability 正例：
JEV 2895/2994；
Pair Threshold 1261/2994。

但是：

JEV 排名准确率83.60%；
Pair Threshold 85.32%。

这提示三种可能：

A. 辅助预测虽正确，但不能提供最终关联所需的身份区分信息。

B. 两类证据在最终评分融合时被错误使用，甚至相互抵消。

C. 真实关联监督、候选覆盖或当前身份证书不足，使模型无法将辅助预测转换成正确的 Global ID 决策。

请针对 A/B/C 分别设计实际可执行的测试，不要直接归因于训练不足。

建立：

`QUESTION_TO_ASSOCIATION_DIAGNOSIS.json`

`QUESTION_TO_ASSOCIATION_REPORT.md`

### 实验一：辅助问题对最终决策的因果贡献

使用已经训练完成的同一个 JEV checkpoint，在相同真实状态和候选集合下对比：

1. 完整 JEV。
2. 保留 Cross，屏蔽 Stability 对最终评分的影响。
3. 保留 Stability，屏蔽 Cross 的影响。
4. 保留两种表示，但使用简单平均。
5. 将两个真实问题的预测分数显式送入一个轻量关联融合器。
6. 使用独立 Reader 处理两类证据，而不是共享最终方案 Reader。

第5、6项若需要新增训练，必须使用新的实验ID和事前冻结配置，并提供相同数据与预算下的普通 MLP / Attention 对照。

必须区分冻结权重干预和重新训练对照；二者不能混为架构因果证据。

输出：

辅助问题预测变化；

具体 Global ID 关联变化；

已认证 N01/N10；

UNKNOWN 改配；

关联排名变化；

完整在线状态是否受到影响。

重点判断：哪一个问题真正提高了最终身份决策，哪一个只是提高了分类准确率。

### 实验二：检查真实标签定义是否一致

现有 R2 报告存在不同协议下的 Question Disagreement 统计。

例如较早的审计与后来 Persistent Question 标签记录使用了不同的目标定义。

请追踪：

`R2_QUESTION_SUPERVISION.json`

`R2_PERSISTENT_QUESTION_PROTOCOL.json`

`R2_ANCHOR_SUPERVISION.json`

`R2_CANDIDATE_AND_QUESTION_AUDIT.json`

确认：

- 当前训练究竟使用哪一版标签。
- Cross 与 Persistent 的准确含义。
- 哪些差异来自正式的标签语义修订。
- 哪些样本因为历史混合而保持 UNKNOWN。
- 有没有标签构造与推理信息不一致。
- 是否把同一人的大量相邻帧当成独立训练纠错事件。

禁止事后修改已经用于 R2 训练的标签以制造新结论。

### 实验三：辅助分类与关联目标是否一致

将已认证当前身份关联分成：

- 两个辅助问题都正确，最终关联正确。
- 两个辅助问题都正确，最终关联错误。
- 只有 Cross 正确。
- 只有 Persistent 正确。
- 两者都错误。
- 正确历史身份未进入最终可评价方案。
- 存在 UNKNOWN，无法认证最终关联。

重点找出：

**两个辅助问题都预测正确、但最终 Global ID 关联错误的事件。**

对这些事件检查：

具体候选 ID；
其他摄像头历史；
早期外观原型；
原始关联分数；
JEV 最终修正；
方案排名；
是否存在合法正确替代；
实际原生提交后的身份状态。

如果根本不存在可认证正确替代，不能把它定义成 JEV 排名失败。
