# JEVTrack 第一版：方法与证据边界

第一版沿用冻结 Phase XIV Multi initializer 与 Phase XV 原生 Gallery/Bank/ID commit。共享256D状态供两个64D Reader读取：其他摄像头历史是否支持当前人物、当前选择是否继续已认证的自身摄像头前驱 Global ID。未知/重复/混杂历史只作为 UNKNOWN mask，不训练未来安全价值，也不启用 learned WRITE、REACT、hard quarantine 或 soft-memory。

新增模块为169,092参数；同证据Attention168,964、MLP154,980、DeepSets159,492。所有强新控制继承同一4,231,173参数已训练基座、收到同样输入和监督，因此检验新增结构的独立增量，不能包装成从零预训练完整 JEV 比完整普通架构优越。线性方法的关联修正只有8个融合参数，但共同辅助监督网络仍计入总注册/计算参数，不能把系统开销写成8参数。

共享状态覆盖本次原生MATCH事件的所有当前检测与全部合法active身份历史，四槽明确区分最近/全局/自身相机/其他相机。相机提交仍按原生顺序；第二相机读取已经变异的真实状态并重新编码。共享指同一次原生事件中的问题复用，不是两个不同commit强行共用旧状态。Bank身份使用冻结原生恢复流程，不声称构建了统一生命周期全状态决策。

原Hungarian完整primary MATCH分配始终包含；只在当前合法分数存在竞争/歧义时生成最多三项约束求解替代。候选无GT/未来帧，容量仅在单相机事件内为1；不同相机仍可合法使用同一Global ID。每项primary分配包括private DEFER，后续Bank恢复与new ID由原生流程执行。这里不能把DEFER预先标为最终NEW，也不把primary计划冒充完整生命周期动作。

先训练可单独检验的逐边修正，再用非加性PlanReader评估联合检测关系。MLP、DeepSets、Attention、规则/阈值使用相同方案。评分×求解2×2针对相同逐边分数空间；Hungarian不优化非加性计划分数，joint机制需额外同方案控制，不能混称为一个纯求解器因果效应。初始边及联合评分修正都为0，191次真实原生提交的所有ID、事件和最终状态与新模块OFF的XIV/XV基线完全一致。

监督与损失只含当前GT匹配、跨相机已认证过去支持、可观察前驱连续性及当前改变行的分配排名。所有改变行必须双方选项已知；不因某个未知候选分数高就把它当负例。保持UNKNOWN语义与当前完整分配监督不等于长期安全Gate通过。四个TRAIN视频共有270个两个目标不同的已知边，TRAIN16共同已知标签无差异，不能凭两个Head宣称独立动态问题贡献。

训练预算为128 Tiny、1000 Pilot、正式累计至多4000；新梯度只进入TRAIN12/13/14非旧预留时间块。TRAIN16只作已暴露控制器审计，DEV17/18/19不调参。各方法完全相同监督/抽样/更新，保留三个种子。候选置换、零候选、GT字段拒绝、初始原生状态合同已用真实TRAIN输入测试通过。性能、训练后非加性、校准、多问题敏感性、完整视频延迟/FPS仍待实测。
