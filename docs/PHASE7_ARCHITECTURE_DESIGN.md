# Candidate-conditioned lifecycle design — conditional, not an achieved result

P0.5 rejects expansion of the current state-only MATCH architecture. This document specifies a bounded alternative research hypothesis; implementation/fitting is conditional on native MiniSet eligibility. Frozen B2 and its production checkpoint are preserved. A candidate prototype is not presented as trained or successful while the gate is unresolved or blocked.

Use the actual 12 online candidate fields in `NATIVE_CAUSAL_MINISET_V1_SCHEMA.md`, the same 64 state features, semantic candidate order/IDs, a genuine NEW option, and typed masks. Do not invent depth, motion predictions, uncertainty estimates or missing low-score boxes. Candidate IDs accompany assignment metadata and never enter scalar network features. Candidates are generated by frozen GMT; absent correct identity is a generator coverage failure, not a selector error.

A minimal proposed DeepSets core has candidate phi: 12→64→64, state encoder: 64→64, mean/max set pooling, 8-dimensional question embedding, global context: (64+64+64+8)→64, and shared candidate/context scorer: 128→64→2. The two outputs have distinct definitions: probability of current identity correctness and future action utility Q. A 64→3 action gate supports the existing native triage interface. Proposed 8→64 MEMORY and 13→64 REACT adapters retain typed current legal spaces. Including three question embeddings and all adapters/gate, the proposed module has 32,093 parameters, near frozen B2's 34,080. MATCH dense-linear MAC estimate is 13,184N+17,088 for N candidates, excluding activations/pooling/calibration. These are design calculations, not a measured implementation or latency result.

Permutation equivariance follows shared candidate phi and shared candidate scoring; invariant mean/max context is recomputed over legal candidates. Add NEW as a separate semantic option, never a fake historical ID. Current candidates compete globally: independent per-row argmax cannot commit conflicting identities. Local edge values cannot be assumed additive; the bounded joint-rejection audit quantifies this.

The current native production hook accepts ACCEPT/REASSOCIATE/NEW, rejects selected edges, globally re-solves **raw** GMT scores, and revalidates every proposed edge with binary legal actions. It does not yet expose a verified direct candidate-value submission interface. Candidate-Q ranking must therefore first receive a separately versioned, tested one-to-one assignment contract with exact commit, MEMORY order and stale-bank semantics; changing solver costs requires all compared candidate controllers to use that same operator. Do not silently replace raw-score Hungarian for only JEV or claim candidate selection is already implemented.

Future comparisons, only with qualified data: ordinary candidate MLP/DeepSets versus typed action-conditioned JEV using identical records/candidate evidence/legal support/native solver, ≤1% parameter gap and separately matched measured compute. Compare correctness versus H8/H16/H32 counterfactual supervision on identical networks. Compare triage versus direct legal candidate choice only under verified native support. A successor-state variant may use actual deterministic immediate consequences for all feasible actions; it may not use future annotations or commit the counterfactual to the factual branch. Shared versus independent heads is allowed only if all three questions independently pass supervision and native parity gates.

Training would use fixed last-epoch AdamW budgets, frozen train07/val06, validation-only calibration, disjoint preregistered controller-heldouts, and proper NLL/Brier/ECE/risk-coverage diagnostics. Temperature scaling and cross-entropy are not RLCD. CPU/GPU median/p95 latency, exact executed MACs, peak extra memory and calls/frame must be measured on a dedicated comparable setup before efficiency claims. Current shared-GPU online timings are instrumented but are not such a benchmark.

WHAT DID WE LEARN? A stronger ordinary normalized MLP removes much of the apparent state-only architectural advantage. Candidate conditioning is a testable alternative, not a result inferred from the P0.5 failure. Missing candidate coverage, insufficient action winners or an absent native interface can block it even when a network is easy to write.
