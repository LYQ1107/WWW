---------------------------------------------
4.1 分析三种错误
---------------------------------------------

E1：GMT 当前关联错误，
并且合法候选中存在能够认证的正确 Global ID。

这是最有价值的可纠错样本。

E2：GMT 当前正确，
但其他候选分数接近。

新模块必须学会不要破坏正确结果。

E3：当前根本不存在可认证正确合法候选，
或原生身份历史已经严重混杂。

不能把 E3 当作普通重评分能够直接解决的问题。

必须区分：
- 错误身份合并；
- 错误身份拆分；
- 新身份错误创建；
- 跨摄像头身份错误；
- Bank 恢复错误；
- 长期身份持续不一致；
- 正确身份候选缺失。

离线 GT 只能用于标注或诊断，
不能成为推理时的输入。

如果多个预测 ID 与同一 GT 人物兼容，
不能随意把它们都视为唯一正确的 Global ID。

若唯一目标无法可靠确定，
必须标记 UNKNOWN。

---------------------------------------------
4.2 评估可纠错上限
---------------------------------------------

使用已有授权 TRAIN 和现有 GMT 推理结果。

统计：

1. GTA 原来已经正确的比例；
2. GTA 当前错误且合法正确候选存在的比例；
3. 这些错误中有多少属于跨相机身份冲突；
4. 改变这些关联后，可能产生多少新的错误；
5. 现有 Gallery 中有没有足够的跨相机证据；
6. 当前身份错误是否集中于少量高风险事件。

可以进行 GT 离线 oracle 上限诊断，
但必须严格标注 ORACLE，仅用于分析。

不得将 oracle 决策作为正式可部署模型结果。

如果 GMT 错误主要来自检测缺失或候选不存在，
立即记录这一事实，不要用复杂 Reader 硬解。

保存：
reports/GMT_JEV/GMT_ERROR_OPPORTUNITY.json

====================================================
五、P2：实现 MCMT-specific JEV-inspired 模块
====================================================

注意：不是重建原来的 JEV。

我们实现的是：

Cross-Camera Identity Conflict Correction

暂定简称：
CIC-JEV

核心思想：

GMT 已经负责主要的视觉关联。

CIC-JEV 只判断：

“当前 GMT 的某次关联有没有足够可信的
跨摄像头身份依据？”

如果 GMT 结果可靠：
尽量维持原始关联。

如果 GMT 存在明显的候选竞争、
不同摄像头的历史证据互相矛盾：

利用当前合法历史进行轻量修正。

---------------------------------------------
5.1 输入特征
---------------------------------------------

从真实当前状态中提取：

A. GMT 原始关联信息

- GTA 关联分数；
- top1 分数；
- top2 分数；
- top1-top2 margin；
- 候选数量；
- 分数分布和不确定性。

B. Global ID 历史

- 当前 ID 历史观测数量；
- 距上次观测的时间；
- 历史外观可靠性；
- 已有 Gallery 外观摘要。

C. 跨摄像头证据

- 当前相机的历史外观相似度；
- 其他相机历史外观相似度；
- 当前相机与其他相机支持程度是否矛盾；
- 跨相机支持的观测数量；
- 身份历史的一致性。

D. 当前关联合法性

- 是否为当前合法候选；
- 是否涉及冲突的 Global ID；
- 是否存在其他高分候选。

如果旧 Gallery 无法直接按摄像头提取历史，
可以增加只在内存中维护的极小状态表，
保存已经提交的外观摘要和摄像头来源。

不得引入未来信息。

不得在推理时读取 GT。

不得错误地比较不同摄像头的图像坐标，
也不要默认不同相机之间的 IoU 有意义。

数据量不足的情况下，
不要构建新的大规模特征缓存。

---------------------------------------------
5.2 最小模型
---------------------------------------------

优先实现：

Small Shared Identity Context
          +
Question-Conditioned Risk Reader
          +
Residual Association Correction

不要使用十几层 Transformer。

不需要完整 JEV 的三阶段复杂结构。

建议内部维度 32 或 64。

尽量将额外可训练参数控制在
100k 以下；如果需要更多参数，
必须说明原因并做容量对照。

输出：

1. 某个关联是否值得干预的风险；
2. 对当前合法候选的分数修正。

核心公式：

S_new(i,j) =
S_GMT(i,j) + gate(i,j) * delta(i,j)

其中：
S_GMT 是原始 GTA 聚合后的身份关联分数。

gate 根据冲突证据决定干预强度。

delta 是小型模型计算的修正量。

必须保证：

Adapter OFF 时完全等于原 GMT。

Adapter ON 且 delta 为 0 时，
也保持原始 GMT 分数与决策不变。

新增残差采取零初始化或等价安全初始化。

注意避免 gate 与 delta 同时初始化为
导致梯度完全消失的状态。

对 residual 设置合理上界，
不允许任意大幅改变 GTA 分数。

不得输出非法 Global ID。

最终身份分配仍由原生匹配约束执行。

不得在新模块里重新维护一套独立 Gallery。

---------------------------------------------
5.3 JEV-inspired 的具体体现
---------------------------------------------

只选择适合任务的思想：

1. Shared Identity Evidence：
   多个关联问题共享当前全局身份状态。

2. Question-conditioned Reasoning：
   对每个检测-身份候选评估其特定的
   跨摄像头证据与冲突。

3. Typed, Legal Decisions：
   对当前合法身份候选给出可执行评分。

4. Minimal Intervention：
   不在没有证据时随意覆盖原始 GTA。

但不能因为使用 Question/Reader 名字，
就声称 JEV 的独立优势已经证明。

必须通过真实消融证明这些设计有价值。

不能直接换成 Strong Fixed。

修复无果则报告真实阻塞。

GTA 的可纠正错误很少。

不要训练大型模块。

转为研究已有合法候选的保守校准，
判断是否存在轻量、可部署的正向增益。

MLP 改善了 GMT，但 JEV 不改善。

保留普通 MLP 作为当前最佳研究方法。

不强行把 JEV 塞进网络。

只有存在明确可解释的结构差距，
才允许一次最小 JEV 调整。

情况 D：
JEV 改善了局部分数，但在线 HOTA 降低。

优先检查错误干预、
原生提交、候选覆盖和状态传播。

不能仅报告局部指标。

情况 E：
HOTA 提高但 CVIDF1 或碎片变差。

判为未通过完整身份稳定性门槛。

不要将其宣传为突破。

情况 F：
取得稳定开发集正向结果，
但缺独立测试资格。

保留候选方法，冻结配置，
标记 DEVELOPMENT_POSITIVE。
