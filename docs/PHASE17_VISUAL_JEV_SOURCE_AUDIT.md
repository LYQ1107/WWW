# Phase XVII source audit

Six immutable external checkouts and exact inspected file/function hashes are recorded in EXTERNAL_CODE_MANIFEST.json. Source inspection is complete; runtime parity and MCMOT identity performance are separate pending experiments. The implementation does not claim replication of unpublished commercial Jev.

## Visual Jev function audit

`VDM.prepare_group` processes one image with system/user prefix and public text, expanding real image tokens once. Each independent suffix contains question, actual candidate descriptions and the final assistant `Answer:` readout position. It rejects K>16 instead of truncating. Full concatenated token IDs are passed to `get_rope_index`; the returned three-axis M-RoPE positions are sliced for prefix/suffix. `split_ids` in prompts asserts BPE prefix compatibility, but `prepare_group` constructs suffix IDs separately rather than invoking that assertion: our teacher must explicitly compare full tokenisation before claiming parity.

`_prefill_prefix` encodes image and Qwen3-VL DeepStack features, scatters image embeddings into prefix positions, runs the language tower with those features and a DynamicCache. `_fork` clones contiguous attention keys and values; expanding batch dimensions and cloning consume time/memory. It has no generic recurrent/conv state copying and is specific to this all-attention backbone. Independent branches extend copies, not the public cache.

`run_prefix_share` executes each suffix serially. `run_prefix_share_batch` left-pads suffixes, creates a prefix+suffix attention mask, slices each full M-RoPE position stream and runs all suffixes together. Public visual DeepStack contributions already reside in prefix cache; suffix-only execution does not add new image tokens. Question-specific instructions and other questions' answers must never be present in shared public context.

`_readout` applies the backbone's original `lm_head` to the final hidden state, selects verified single-token ` A`–` P` logits, masks valid slots and normalises within the question. Optional `DecisionHeads` provide dedicated choice/claim/answerability controls. `with_heads=False` removes these heads, not task adaptation: the default released adapter was answer-supervised LoRA. `train.py` a2/a2k use answer-SFT; `losses.answer_sft_loss` trains the next-token answer through the full vocabulary, whereas dedicated-head controls use typed loss and separate trainable head parameters. A newly random typed head is not a fair trained performance comparator.

Pretrained no-head, released answer-LoRA no-head and trained dedicated-head variants must be distinguished. This stage has not trained identity-task LoRA or a head control. Published visual-QA outputs cannot substitute for our identity experiment.

All paths aim for identical decisions but floating-point/batching masks require measured parity; no numerical PASS follows from source alone. At N=1 sharing adds prefill/fork overhead; at N=4/8/16/32 public work can amortise. Report total wall time, p50/p95, cache construction and clone costs, and time/question separately. External GPU timings are not our V100/GMT online latency. Do not count only the suffix cost.

MCMOT candidate pools may exceed sixteen. Audit Recall@K including absent correct legal identities first. Do not silently crop Top16. Pairwise compatible/incompatible/unknown questions allow all legal candidates to be evaluated but their probabilities still need calibration and may have inconsistent joint semantics. Chunk-plus-none is a hypothesis, not a guaranteed globally normalised distribution. Independently normalised softmax sets are not directly comparable; cyclic candidate order and chunk-layout stability require evaluation.

## Other reusable mechanisms

Valen's dual encoder explicitly separates fused state, typed question evidence and per-candidate reading. QuestionBlock projects state once while flattening question queries; CandidateBlock reuses memory KV across bounded candidate chunks. Its Qwen backend has bilinear, MLP, role-MLP and mixer heads; these are additional trainable heads, distinct from Visual Jev LM readout. Qwen batching pads independent branches and preserves readout positions; batching alone does not prove cached-prefix reuse. RLCD is an explicit GRPO-like experiment with categorical rollouts, detached advantages, confidence/correctness reward and optional KL/Brier, not TypeSafe's commercial training implementation.

OneJev explicitly copies attention and recurrent/conv layer states. Unknown cache types fail instead of silently skipping state. Its many-option path adds a shared none choice, weights within-chunk probabilities by non-none mass and renormalises; this is a heuristic requiring independent calibration. Its MM preparation cache key uses Python object identity for state and media: in-place mutation could retain stale preparation. A tracker needs content/version keys for video, frame, camera, candidate histories, model and prompt, and invalidation after commit. Copying only KV for Qwen3.5 is invalid.

Jev-Mem separates stored narrative observations, graph/vector candidate generation, relation assessment and stop/continue decisions. Calls, nodes, edges, latency, depth and fallback are budgeted. Cache keys include serialised content/backend/model/questions. Mock probabilities are explicit fixtures, never valid tracking results. Borrow separation of raw forensic records and decision evidence, not its semantic-entity ownership assumptions or remote endpoint.

NanoJev `DecisionModel.forward` encodes actual semantic candidate leaf paths in one padded forward, reads a shared scalar and optional set attention, then Boolean sigmoid or legal-choice softmax. This reference repeats prefixes; tree sharing is a separate optimisation. Unified game training distinguishes teacher policy/expert targets from actual observed outcomes and lagged-model TD estimates. Real MCMOT labels cannot be inferred from simulator rewards or per-edge values presented as joint Hungarian assignment value.

vLLM-Jev serving uses locked compile and bounded asynchronous inference, readout-position pooling, within-request task reuse, cancellation and random per-request salt. Optional hybrid prefix checkpoints track full attention/Mamba components, active references and dependent invalidation, with version-sensitive private scheduler hooks. Reuse isolation and invalidation concepts; do not install this stack into frozen GMT or imply faster inference improves identity science.
